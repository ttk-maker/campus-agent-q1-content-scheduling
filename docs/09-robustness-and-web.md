## 首轮实际失败与修复

新增 20 项边缘/困难用例首次执行出现 9 项失败、2 项错误；[初始记录](../examples/robustness/initial-failures.txt) 保留原始结果，不能作为最终测试报告。

| 发现 | 原行为 | 修复 |
| --- | --- | --- |
| A→B→A 建议变化 | 旧确认可重新匹配 A 并授权 | 修订号绑定确认，建议/素材变化删除旧确认 |
| 旧页确认 | 无确认版本比较参数 | 页面携带确认指纹，服务比较当前修订 |
| 新占用 | 已 ready 草稿仍保持 ready | 同步占用时事务内标记需重新审核 |
| 新素材风险 | 输出阻断但数据库旧草稿仍 ready | 新运行先复验旧草稿的素材与规则 |
| 保存竞态 | 审核后的素材快照变化未察觉 | 保存前重读源资料，变化则拒绝并要求重验 |
| 空白字段 | 空白标题/频道被当作有效 | 去空白后判缺失；必填基线不可从规则列表删除 |
| 极端输入 | 超长 ID、日期候选溢出 | 提前验证 ID 长度、可计算的日期范围 |
| 非法模型响应 | choices=null 抛出未处理 TypeError | 包装为脱敏 ModelError |
| 保存后模型失败 | Trace 错误断链 | 保留已保存事实，失败步骤正确串联 |

Web 联调进一步发现：确认旧任务不能把占用快照回滚到旧版本。确认执行使用最近已接收的资料快照，新增专门 HTTP 回归测试。

## 404 根因与修复范围

用户提供地址：http://localhost:11434/v1。实测 GET 404；/api/version 和 /v1/models 为 200。该地址是模型 API 前缀，之前没有 Web UI，不能将它修成应用页面。

本轮新增 http://127.0.0.1:8765/ 工作台及同源 JSON API，支持场景选择、真实/Mock、单项/批量输入、完整占用快照、状态显示、独立确认、Trace 导出和持久草稿列表。原模型服务不修改，网页地址与模型地址在 README 和手册中分别说明。

## 验证范围与限制

分层冒烟使用确定性 Mock 或对抗模型桩验证工程不变量；HTTP 适配测试不冒充真实模型能力。真实模型用例单独保存实际输出与 Trace。上一轮 examples/real/ 是历史完整验收，保留原记录；本轮仅针对改动运行真实边界样本与真实浏览器链路，不把旧报告当作新代码的完整重测。

没有长时间压力测试、不同硬件统计测试或所有随机种子实验；真实模型单轮成功不等价于稳定性保证。服务默认仅本机、同时一个任务，运行历史内存保留最近 100 项，草稿 SQLite 持久化。使用手册说明了这些边界。

真实边界首轮为 3/4 通过。“全部占满”时 Qwen 反复尝试保存并使用错误终态 blocked，守卫全部拒绝，16 步后 budget_exhausted；零草稿、未发布，但未达到期待的 no_available_slot，因此明确算失败。原始 [Trace](../examples/robustness/real-before-capacity-fix/all-slots-full/trace.jsonl) 与 [首轮报告](../examples/robustness/real-before-capacity-fix/report.json) 保留。

修复为 query_slots 明确返回 available_count 和 available_starts，错误终态返回真实合法选项，并在提示中区分规则阻断与时段耗尽；仍由模型选择动作和终态，没有直接由固定分支代替模型结束。针对失败用例重跑后 4 步、约 46 秒返回 no_available_slot。最终 4/4 是首轮其余三例与该针对性复测的汇总，不声称同一批一次全过。
