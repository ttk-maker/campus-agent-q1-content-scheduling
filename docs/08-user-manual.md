# 使用手册：素材审核与发布排期工作台

## 1. 先打开正确的地址

**网页地址：[http://127.0.0.1:8765/](http://127.0.0.1:8765/)。**

用户报告的 http://localhost:11434/v1 是 Ollama 的 API 基础地址。实测该路径 GET 返回 404，但 /api/version 和 /v1/models 返回 200；不是模型服务宕机。上一版只有 CLI 和 SVG 原型，没有 Web 页面。本轮新增了浏览器工作台、HTTP 后端和本手册。

| 地址 | 用途 |
| --- | --- |
| http://127.0.0.1:8765/ | 用户工作台 |
| http://127.0.0.1:8765/manual.html | 浏览器使用手册 |
| http://127.0.0.1:8765/api/health | 工作台健康检查 |
| http://localhost:11434/v1 | 模型 API 基础地址，不是网页 |
| http://localhost:11434/v1/chat/completions | 程序发送 POST 模型请求的路径 |

## 2. 安装与启动

需要完整 Python 3.10+，Web 与 CLI 运行均无需第三方 Python 库。Windows 开发机使用 py -3.10：

~~~powershell
git clone https://github.com/ttk-maker/campus-agent-q1-content-scheduling.git
cd campus-agent-q1-content-scheduling
py -3.10 -m src.web
~~~

浏览器打开工作台即可。也可在仓库目录执行 scripts/start-web.ps1。Linux/macOS 使用 python -m src.web。服务只绑定本机回环地址，不能作为公网多用户部署直接使用。

真实模型模式默认使用本地 Ollama 的 qwen2.5:7b-instruct；离线模式不需要 Ollama。其他机器按需安装 Ollama 并下载模型：

~~~bash
ollama pull qwen2.5:7b-instruct
~~~

服务端环境变量 MODEL_BASE_URL、MODEL_NAME 可覆盖默认设置；远端服务还需 MODEL_API_KEY。密钥不在前端输入或回传浏览器。

## 3. 先运行题目中的冲突示例

1. 选择“时段冲突 · 18:00 → 建议 19:00”。
2. 首次可选“离线演练”；验证模型决策时改选“真实模型”。
3. 保持素材 M01、2026-11-07 18:00 和硬性要求。
4. 点击“审核并生成草稿”，等待结果。
5. 应看到审核通过、保存成功、建议 19:00、待确认改时、生效时间为空、未发布。

页面时间统一显示北京时间；下载结果中的标准化时间可能为 UTC，11:00+00:00 等于北京时间 19:00。示例日期是固定的合成测试日期，并非实时生产排程。

## 4. 确认改时

点击结果卡片中的“确认改为…并重新审核”，核对弹窗后确认。后端记录对**具体草稿修订版本**的同意，再用最新排期资料重新审核和检查占用。成功时同一 draft_id 变为 ready，仍未发布。

如果 19:00 已被其他任务占用，会建议新的时间并再次待确认；旧确认不能授权新的时段。旧页面与当前草稿版本不一致时会提示重新审核，不能通过反复点击绕过。

## 5. 重复提交、补资料和改排期

- 防重复：保留相同请求编号和原始需求再次提交，返回 existing，同一草稿 ID。
- 改变原始时间等需求：生成新编号。新编号代表新的业务请求，不会删除旧草稿，旧 ready 草稿可能占用时段。
- 补充素材资料：展开高级区域，在 data.assets 或 data.supplements 中填写来源资料，再用原编号重新审核。
- 测试时段变化：修改 data.occupied 中的 start。该列表是完整外部排期快照，提交时整体同步；同编号重提会看到新的占用。
- 批量：高级区域的素材请求列表是实际提交值；上面的单项表单只编辑列表第一项。
- 新素材或规则导致旧判断失效时，草稿变为 needs_revalidation（需重新审核），不会继续显示为可用草稿。
- 删除某条外部占用与删除草稿不同；本版没有取消草稿功能。需要全新演示可启动独立数据库，避免历史占用影响结果。

~~~powershell
py -3.10 -m src.web --port 8766 --db runtime/fresh-demo.db
~~~

## 6. 理解状态

| 显示 | 含义 | 下一步 |
| --- | --- | --- |
| 审核完成 / 可用草稿 | 当前资料和时段验证通过，仅草稿 | 核对结果 |
| 待确认改时 | 建议改变原始时间 | 阅读建议后由用户确认 |
| 待补充资料 | 缺少必需字段 | 补齐资料再提交 |
| 风险阻断 | 命中审核规则 | 处理风险后重新审核 |
| 暂无可用时段 | 候选范围内全部占用 | 调整业务要求，用新编号提交 |
| 需重新审核 | 旧草稿对应的资料或排期变化 | 重新运行审核 |
| 执行失败 | 工具或模型失败 | 查阅错误、Trace 和实际保存状态 |
| 达到上限 | 动作预算耗尽，本次未完成 | 检查 Trace，再决定是否重试 |

整体状态与保存事实分开：模型可能在写入成功后出错，此时会显示执行失败但草稿已保存。重试必须保留请求编号，不能据此假设数据库为空。

## 7. Trace、导出和刷新

“查看动作与工具返回”展示步骤、参数、返回与下一步，不包含内部思维过程。“导出记录”下载包含输入、输出和 Trace 的 JSON。

同一服务进程中刷新网页可恢复最近任务及输入；页面关闭不会取消后台执行。运行中的任务限制为一个，重复提交会得到“已有任务正在执行”。服务重启后内存中的运行记录不保留，但 SQLite 草稿保留；可重提相同编号验证原草稿。

默认库为 runtime/web-drafts.db，CLI 默认库为 runtime/drafts.db，两者分开。两种入口需要共享状态时显式传入相同 --db，并避免同时替换占用快照。

## 8. 常见问题

- 打开 11434/v1 显示 404：这是 API 基础地址，请打开 8765 网页。
- 8765 拒绝连接：工作台未启动或已退出，重新执行启动命令。
- 8765 被占用：使用 --port 8766，并打开对应端口。
- 真实模型失败：检查 Ollama 是否运行及 ollama list 是否列出模型；单次请求有 45 秒超时，不会自动伪装为离线成功。
- JSON 错误：检查双引号、逗号、字段类型和时区。请求最多 256 KB，素材最多 200 项，单次请求最多 50 个素材，UI 步数上限 1–100。
- 草稿版本过期：刷新并重新审核，不能复用旧页面的确认。
- 已存在草稿影响演示：使用新的数据库路径，而非删除正在运行的数据库。
- 操作权限提示过期：刷新页面以获取当前服务会话。
- 想停止服务：前台终端按 Ctrl+C。服务重启后，先查看草稿再判断是否需要重试。
