# 动作流原型与痛点强化

本轮经用户确认交付可导入 Figma 的 SVG。图稿保留文本和矢量节点，可拖入 Figma Design 画布；并非已在 Figma 创建的在线文件。Mermaid 源文件用于版本跟踪。

## 参考实例的准确行为

M01 无风险，原定 18:00 已占用：模型查询候选并建议 19:00；工具可保存 pending_confirmation 草稿，requested_at 仍为 18:00，suggested_at 为 19:00，effective_at 为空，published 始终为 false。用户确认 19:00 后，再审核、再查冲突；成功则更新同一草稿为 ready，仍不发布。重复提交不新增草稿；保存失败明确 failed。

## 痛点与强化计划

| ID | 痛点 | 架构基础 | 基础实现后强化 / 验证 |
| --- | --- | --- | --- |
| P1 | 缺资料导致凭空补全 | 素材与补查来源分离 | 缺失后补查成功 / 补查仍缺失两条路径 |
| P2 | 规则风险被模型忽略 | 保存工具强制重验规则 | 跳过审核、恶意素材指令、绕过阻断 |
| P3 | 改时越权、旧确认误用 | 原始要求不可变，确认不向模型暴露 | 伪造确认、换建议时间、元数据变化后旧确认失效 |
| P4 | 查询可用但保存时冲突 | 事务内复验占用 | 动态占用注入、并发请求、确认时被占用 |
| P5 | 重试产生多份草稿 | 主键唯一、输入摘要校验 | 顺序重复、并发重复、同键不同请求 |
| P6 | 保存失败却报告成功 | 输出来自实际提交结果 | 故障回滚、模型虚假 finish、确认缺失 |
| P7 | 无限循环或非法工具 | 全局预算、参数校验 | 持续非法动作、预算耗尽、没有发布接口 |

实施顺序：文档与协议 → 核心循环与存储 → 六类场景 → 痛点强化测试 → 真实模型路径 → 复现与交付。每阶段独立提交，保留可审查历史。
