# 需求、范围与验收

用户：内容运营与审核人员。目标：找出待处理素材，形成无冲突、可确认且保存结果可信的排期草稿。

输入：请求 ID、素材 ID 列表、每项原始发布时间（带时区）、硬性要求标志、素材元数据、补充资料、已有占用、审核规则。全部演示资料均为合成数据。

输出：逐项审核状态、风险原因、原始时间、建议时间、生效时间、待确认项、草稿 ID、保存状态和运行终态。未确认的改时不产生生效时间。任何输出均不表示已发布。

## 必验六类场景

| 编号 | 场景 | 成功标准 |
| --- | --- | --- |
| A01 | 正常排期 | 规则通过、时段空闲，保存 ready 草稿，仍为未发布 |
| A02 | 信息缺失 | 明确缺失字段，选择补查或请求补充；不得虚构元数据或保存 ready 草稿 |
| A03 | 规则风险 | 报告具体风险与规则，阻断；用户改时确认不能绕过规则 |
| A04 | 时段冲突 | 原定 18:00 被占用时建议空闲 19:00，保留原要求，待用户确认 |
| A05 | 重复提交 | 相同 request_id 和素材的相同请求只产生一份草稿；同 ID 不同需求明确拒绝 |
| A06 | 保存失败 | 返回 failed，不伪造草稿 ID 或成功状态，事务回滚 |

扩展验证：换一个占用时段后重跑、用户确认后重查时段、旧确认不适用于新建议、并发写入互斥、保存前占用变化、模型非法动作与越权确认、步数耗尽、跨时区等价时刻、批量素材部分失败。

## 业务约定

- 时段按素材 channel 与 duration_minutes 使用半开区间 [start,end) 判定重叠。带时区时间统一到 UTC；展示保留原始要求。
- 请求 ID 由调用方稳定提供，作为幂等键的一部分；重试必须复用该 ID。不同 ID 是不同业务请求，不自动视为重复。
- 原始要求不被模型修改。更改硬性时间必须有独立用户确认；本项目对非硬性要求也保守地显示待确认。
- 待确认草稿可保存建议时间，但 effective_at 为空且不占用已确认排期；它只是提议。确认后重查规则与冲突，事务内重新校验后才能变为 ready 并占位。
- 已通过规则的 ready 草稿占用时段以避免多份可执行草稿互相冲突；未保存的建议不保证未来可用。
- 风险采用合成规则，作为业务工具的明确判断依据；不宣称覆盖真实内容安全审核。
- 单次 CLI 可处理多项素材，逐项返回状态；执行预算覆盖整个请求。

## 非目标

真实发布、真实平台账号接入、生产级身份认证、分布式调度、复杂自然语言日期解析。CLI 操作者是可信用户；生产环境必须通过认证主体绑定确认。
